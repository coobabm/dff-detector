# Detecting AI-generated faces: DeepFakeFace replication + OpenAI images + AI video / face-swap detection

Real-vs-AI face detectors trained from scratch on one M2 Max Mac, used to answer three questions:

1. **Can a detector recognise generators it has never seen?** (replicating the detector / generator *arms race*)
2. **How many images from a new generator does the detector need to learn it?** (OpenAI's gpt-image family as the test case)
3. **Does it work on video?** (FaceFusion face swaps; AI-generated video from Veo / Sora / Kling and others)

Includes a Gradio web UI (中文 / English / 한국어): images and videos go into the same upload box and are routed to the right specialist model. Images get an AI-generated probability + Grad-CAM heatmap; videos are checked by both an AI-video detector and a face-swap detector.

![OpenAI samples](docs/openai_samples.jpg)
*Every face above was generated by gpt-image-1.5 / 2 / 2.5. None of these people exist.*

## Key findings

| | Result |
|---|---|
| Train on one generator, test on an unseen one | Often drops to chance (AUC 0.3–0.7) |
| Train on all three DFF generators (`all`) | > 0.9 AUC on each, but only 0.44 AUC on OpenAI images |
| Fine-tune with **50** OpenAI images | OpenAI detection rate 3% → **83.5%** |
| Fine-tune with **500** | **98.0%**; more barely helps (897 images: 98.5%) |
| False positives on modern real photos | 0–1.4% (Pexels / PPR10k / FFHQ / Flickr30k / EasyPortrait) |
| StyleGAN faces (never seen) | detected 0% → **87–99%** after adding 4,500 images |
| FaceFusion face-swap videos | loose framing + small model: missed → **tight face crop + EfficientNet-B4: AUC 0.93–0.98; all 4 local face-swap test videos caught** |
| AI-generated video (Veo / Sora / Kling / talking heads) | held-out AUC **0.968**, 93.8% of real videos correct; **re-uploaded, re-compressed web videos are still unreliable** |

**In one line: a detector only knows the kinds of generator it was trained on, but a few hundred samples from a new generator are enough to catch up. For video, the key is to look at the face up close.**

### 1. Cross-generator test (DeepFakeFace)

![cross generator](docs/cross_generator.png)

- Trained on SD text-to-image only → face-swap AUC 0.49 (chance).
- Trained on face swap only → text-to-image AUC **0.305**, worse than chance: the model rates diffusion fakes as *more* real than real photos.
- The inpainting-trained model transfers best (0.965 on text-to-image). Inpainting forces it to learn local seams, and those traces generalise better.
- Test set contains only people never seen in training (split by IMDB-WIKI person ID).

### 2. OpenAI learning curve

![learning curve](docs/learning_curve.png)

Tested on the same 200 held-out OpenAI images + 3,000 real photos from 6 sources:

| OpenAI images added | OpenAI AUC | OpenAI detected | Real correct | Old DFF fakes detected |
|---|---|---|---|---|
| 0 | 0.412 | 3.0% | 95.2% | 76.7% |
| 50 | 0.976 | 83.5% | 98.1% | 79.6% |
| 100 | 0.991 | 90.5% | 98.0% | 80.3% |
| 200 | 0.994 | 93.5% | 98.1% | 79.5% |
| 500 | 0.998 | 98.0% | 97.6% | 81.3% |
| 897 | 0.999 | 98.5% | 97.8% | 79.4% |

gpt-image-1.5, 2 and 2.5 are each detected at about 98%. Among real photos, only the old DFF wiki photos have a high false-positive rate (about 10%; they are small and blurry). Full numbers in [`results/`](results/).

### 3. StyleGAN (GAN-generated faces)

The image model had only seen diffusion models (SD, OpenAI) and detected 0% of StyleGAN faces. Adding 4,500 StyleGAN2/3 faces plus real FFHQ faces (StyleGAN was trained on FFHQ, so these are the hardest negatives) gives the final image model `all_image`:

| Test set (never used in training) | Before | After |
|---|---|---|
| thispersondoesnotexist (StyleGAN2) | 0% | 86.8% |
| StyleGAN2-Face | 0.6% | 99.4% |
| StyleGAN3 | 0% | 97.3% |
| 140k Real/Fake (StyleGAN) | 0% | 79.4% |
| OpenAI images | 98.5% | 98.5% |
| Real photos (6 sources) | 97.8% | 97.0% (FFHQ 96.4%) |
| Old DFF fakes | 79.4% | 77.5% |

## Video detection

Video is checked frame by frame: take a set of frames → YuNet finds the largest face → score it → take the median over frames.

### What didn't work: loose framing + small model (4 rounds)

The first approach reused the image models' framing (face ≈ 45% of the crop, so after resizing to 224 px the face is only ~100 px wide) and fine-tuned EfficientNet-B0 on video frames, over 4 rounds:

| Round | What was added | Result |
|---|---|---|
| 1 | Frames from public AI-video / face-swap datasets; real video only from FF++ | Called almost everything fake: only 59% of real videos correct |
| 2 | Real CelebV-HQ videos | 88% of real videos correct, but missed all the local AI videos again |
| 3 | ~300 face-swap videos generated with FaceFusion on this Mac (OpenAI-generated faces swapped in) | Held-out AUC 0.80–0.92, but the local Iron Man swaps still scored 0 |
| 4 | Real (FFHQ) faces swapped into film clips, plus film-look augmentation | New swaps only AUC 0.67–0.77; Iron Man still missed |

Conclusion: the traces of a high-quality swap (edges, skin texture, eyes and teeth) are tiny and mostly invisible in a 100 px face. Part of round 3's good score also came from a shortcut: the swapped-in face itself was AI-generated.

### What worked: tight 380 px face crop + EfficientNet-B4

Switched to the standard face-swap-detection setup: crop only 1.3× the face box, resize to 380×380 (`extract_tight.py`), use the larger EfficientNet-B4 (`train_swap.py`), 16 frames per video. Real and fake videos are generated in pairs and encoded at the same quality; the threshold is chosen on a validation set.

**Face-swap detector** `runs_swap/b4` (1,014 videos: 421 real / 593 swapped):

| Test (people / videos not used in training) | Result |
|---|---|
| FaceFusion hyperswap 1a/1b/1c, alphaface, inswapper | AUC 0.93–0.98, 75–100% detected |
| DF40 inswap / simswap | AUC 0.97–0.98, 100% detected |
| FF++ (Deepfakes, FaceSwap and 3 more) | AUC 0.80–0.96 |
| Real videos | 90% correct |
| **Local Iron Man face-swap videos ×4** (made with the author's own photo, never in training) | **4/4 caught (median 1.00)**; original 0.00 |
| Original re-encoded (q95/80/60, 720p) | All judged real, so the model detects the swap, not the extra compression |
| Swap re-compressed to 720p / crf 28 | Still judged fake (0.98) |

**AI-generated video detector** `runs_aivid/b4` (Veo 2/3/3.1, Sora 1/2, Kling, Wan, Pika, Ray2, Hunyuan, 6 talking-head methods, HeyGen; 2,519 fake + 2,584 real videos, including "web re-upload" copies):

| Version | Change | Held-out AUC | Real correct | Fakes detected |
|---|---|---|---|---|
| v1 | First version | 0.80 | 87% | 57% |
| v2 | + TalkingHeadBench + CelebV real videos | 0.96 | 84% | 92% |
| v3 | + one YouTube-style re-compressed copy of every video (360–720p, H.264 / VP9) | 0.96 | 84% | 94% |
| **v4 (used)** | Real videos doubled (+600 CelebV) | **0.968** | **93.8%** | 88% |

(All four versions compared on the same test set: 991 held-out videos including re-compressed copies. An ensemble of the four did not beat v4.)

**Unsolved:** two AI videos re-uploaded on the web (a Veo 3 clip transcoded by Wikimedia, an AI fake-news video from YouTube) score near the threshold in all four versions; too little trace survives the re-compression. Also, edited videos that mix in real footage get their median score pulled down by the real frames.

## Where the data comes from

Three kinds of data, about 150k images in total. Everything is converted to 256×256 JPEG (quality 95).

### A. DeepFakeFace (DFF): main training set

- Source: [OpenRL/DeepFakeFace](https://huggingface.co/datasets/OpenRL/DeepFakeFace) (Hugging Face, OpenRAIL licence, 4 zips, about 5 GB)
- Contents:

| zip | Class | Count | How made |
|---|---|---|---|
| `wiki.zip` | real | 30,000 | IMDB-WIKI celebrity photos |
| `text2img.zip` | fake | 30,000 | Stable Diffusion v1.5 text-to-image |
| `inpainting.zip` | fake | 30,000 | SD Inpainting (partial repaint of real photos) |
| `insight.zip` | fake | 30,000 | InsightFace face swap |

- All four zips share one layout: `<class>/<00–99>/<personID>_<birthdate>_<photoyear>.jpg`. Each fake has the same filename as the real photo it came from.
- The subfolder number is the last two digits of the person ID, so one person is always in one folder. Splitting by folder therefore cannot leak people between splits: **00–79 train, 80–89 val, 90–99 test**.
- Real photos come in mixed sizes. The DFF authors stretched them to 512×512 before generating fakes, so this project stretches everything to 256×256 and real and fake share the same geometry.
- Full list: [`data_lists/dff_manifest.csv`](data_lists/dff_manifest.csv).

### B. OpenAI-generated faces: made by this project

- Generated with the OpenAI Images API (`/v1/images/generations`, 1024×1024, default medium quality).
- 3 models: gpt-image-2 (434 images), gpt-image-1.5 (332), gpt-image-2.5 (331), **1,097 in total** (1,100 requested; the API rejected 3 with HTTP 400).
- Prompts are random combinations (fixed seed 0, fully reproducible):

```
Realistic photograph of a {age} {ethnicity} {gender} {scene}, face clearly visible, upper body, {photo style}. No text, no watermark.
```

  - 6 ages (young … elderly) × 6 ethnicities × 2 genders × 8 scenes (red carpet, press conference, street, office, sports event, TV studio, …) × 5 styles (2008 digital camera, news-agency photo, amateur phone photo, professional headshot, old scanned photo).
  - Scenes and styles deliberately imitate IMDB-WIKI celebrity news photos, so real and fake have similar subjects.
- Originals are PNG (about 1024–1300 px) and carry OpenAI's embedded C2PA content credentials. For training they are centre-cropped to a square and resized to 256×256.
- Download: [Releases v0.1](../../releases/tag/v0.1)

| File | Contents |
|---|---|
| `openai_faces_256.zip` (26 MB) | 1,097 × 256×256 JPEG (the version used for training) |
| `openai_faces_orig_part1.zip` / `part2.zip` (1.1 GB each) | Original PNGs |
| `openai_meta.json` | Model and prompt for each image |

### C. Modern real portraits: blocking the "sharp = fake" shortcut

DFF's real photos are mostly old and blurry, while OpenAI images are sharp and modern. With only DFF real photos, a model could learn "sharp modern photo means fake". So five more real-photo sets were added:

| Source | Contents | Used | How sampled |
|---|---|---|---|
| [FFHQ](https://huggingface.co/datasets/bitmind/ffhq-256) | High-res Flickr faces (aligned crops) | 4,375 | First parquet shard of `bitmind/ffhq-256` |
| [Pexels Portrait](https://huggingface.co/datasets/gaunernst/pexels-portrait) | Professional portrait photography | 3,000 | Only Pexels IDs < 14,000,000 (uploaded before ~2023, avoiding AI images), random sample |
| [PPR10k](https://huggingface.co/datasets/JarvisArt/MMArt-PPR10k) | Unretouched portrait-shoot photos | 3,000 | Each sample's `before.jpg`, random sample |
| [Flickr30k](https://huggingface.co/datasets/nlphuji/flickr30k) | Everyday photos | 1,458 | 3,000 random files from the zip; about half were macOS `._` metadata files and were skipped |
| [EasyPortrait](https://huggingface.co/datasets/gofixyourself/EasyPortrait) | Webcam selfies (video-call setting) | 3,000 | Random sample from `data/test.zip` |

- All sampling uses fixed seed 0. Non-square images are centre-cropped; portrait-orientation images are cropped from the top to keep the face.
- These photos show identifiable real people, and some licences forbid redistribution, so **this repo does not include them**. The ID of every image used is listed in [`data_lists/`](data_lists/).

### D. StyleGAN faces (`fetch_gan.py`)

| Source | Generator | Used |
|---|---|---|
| [javi22/this-person-does-not-exist-10k](https://huggingface.co/datasets/javi22/this-person-does-not-exist-10k) | StyleGAN2 | 1,500 |
| [gojay/StyleGAN2-Face](https://huggingface.co/datasets/gojay/StyleGAN2-Face) | StyleGAN2 | 1,000 |
| [34data/StyleGAN3_1024x1024_images](https://huggingface.co/datasets/34data/StyleGAN3_1024x1024_images) | StyleGAN3 | 1,000 |
| [TheKernel01/140k-Real-and-Fake-Faces](https://huggingface.co/datasets/TheKernel01/140k-Real-and-Fake-Faces) | StyleGAN fakes + FFHQ reals | 1,000 each |

A random 20% of each source is held out for testing.

### E. Video

| Kind | Source | How |
|---|---|---|
| Face swaps (generated here) | FaceFusion 3.9 on this Mac: hyperswap 1a/1b/1c, alphaface, inswapper; real FFHQ faces swapped into CelebV-HQ interview clips and 4-second segments of raw YouTube videos (incl. films and TV) | `gen_faceswap.py --targets clips/raw --faces ffhq --keep`; real and swapped versions each encoded once at the same quality |
| Face swaps (public) | [FaceForensics++ C23](https://huggingface.co/datasets/bitmind/FaceForensicsC23), [DF40](https://huggingface.co/datasets/ohjoonhee/DF40-Fake-Videos) | `fetch_public_videos.py`; only the needed videos are pulled out of the zips (HTTP range requests) |
| AI-generated video | [34data gen-videos](https://huggingface.co/datasets/34data/gen-videos-veo3) (Veo 3 / Sora 2 / Kling / Wan 2), [GenVidBench](https://huggingface.co/datasets/jian-0/GenVidBench) (Sora / Kling), [Rapidata](https://huggingface.co/datasets/Rapidata/text-2-video-human-preferences-veo3) preference sets (Veo 2/3/3.1, Sora, Pika, Ray2, Hunyuan, Wan, Alpha) | `fetch_rapidata.py`, `fetch_aivid_videos.py`; only videos with a detectable face are kept |
| Talking heads | [TalkingHeadBench](https://huggingface.co/datasets/luchaoqi/TalkingHeadBench) (LivePortrait, Hallo 1/2, AniPortrait ×2, EmoPortrait), DF40 HeyGen | Same |
| Real video | FF++ originals, [CelebV-HQ](https://huggingface.co/datasets/mengtingwei/celebv-HQ-raw-videos) raw video segments and [interview clips](https://huggingface.co/datasets/saeed-5959/celebv_hq_head_talking) | Same |
| Re-compressed copies | One per video above: 360/480/720p, H.264 crf 26–34 or VP9 | `recompress_videos.py` |

Splits group by identity / prompt (a real clip and its swapped versions are in the same group), so people and videos in the test set never appear in training. Neither the videos nor the extracted face crops are redistributed.

## Method

| Step | File | Details |
|---|---|---|
| Data | `prepare.py` | Download DFF → 256×256 → split by person folder, write `data/manifest.csv` |
| Training | `train.py` | EfficientNet-B0 (timm, ImageNet-pretrained) binary classifier. AdamW + OneCycle, lr 3e-4, batch 64, 4 epochs, keep the epoch with best val AUC. Both classes get identical random downscaling / blur / JPEG / crop / flip / colour jitter, so sharpness can't be used as a shortcut. Each epoch uses all real images + an equal random sample of fakes (balanced classes) |
| Experiments | `run_all.sh` | 4 models: `t2i`, `inpaint`, `insight`, `all` |
| OpenAI fakes | `gen_openai.py` | See B above |
| Modern reals | `fetch_real.py` | See C above |
| Zero-shot test | `eval_openai.py` | DFF models tested directly on OpenAI images |
| Learning curve | `openai_curve.py` | 200 of the 1,097 OpenAI images are held out for testing; the other 897 form the training pool. Starting from `all`, fine-tune for 3 epochs (lr 1e-4) with N images (0/50/100/200/500/897). Each epoch: about 6,000 real images (up to 1,000 from each of 6 sources) + 3,000 DFF fakes + 3,000 OpenAI images (the N images resampled). Test reals = 500 from each of the 6 sources, disjoint from training |
| StyleGAN | `gan_finetune.py` | Fine-tune `all_openai` for 4 epochs. Reals: 6 photo sources + all non-test FFHQ + 140k reals; fakes: 4 StyleGAN sources (equal share) + DFF + OpenAI → `runs/all_image` |
| Video, loose framing (old) | `video_scan.py`, `fetch_video.py`, `video_finetune.py` | "What didn't work" above |
| Tight video face crops | `extract_tight.py` | 16 frames per video, 1.3× face box, 380×380 |
| B4 detectors | `train_swap.py` | EfficientNet-B4, batch 16, lr 1e-4, 5 epochs × 1,500 steps; sampling balanced by class and by source; 10% of training groups held out to pick the best epoch and threshold; `--task swap` or `--task aivid`; film-look augmentation (darkening, grading, grain) |
| Face-swap generation | `gen_faceswap.py` | Runs local FaceFusion 3.9 headless; 5 models in rotation, pixel boost 256/512, mask = box + occlusion (xseg_3) |
| Video scan | `scan_swap.py` | `--model runs_swap/b4` or `runs_aivid/b4`, 32 frames, contact sheet |
| Web UI | `app.py` | One upload box: image → `all_image` + Grad-CAM; video → both B4 detectors, flagged if either is above its threshold, with the most likely kind; three UI languages |

## Quick start: web UI

Needs [uv](https://docs.astral.sh/uv/). Uses MPS on Apple Silicon, CUDA on NVIDIA, otherwise CPU.

```bash
git clone https://github.com/coobabm/dff-detector.git
cd dff-detector
uv sync
# Download model weights and unzip in the repo root (gives runs*/…/model.pt)
curl -LO https://github.com/coobabm/dff-detector/releases/download/v0.2/models.zip
unzip models.zip
uv run app.py      # open http://127.0.0.1:7860 and upload an image or video under "Detect"
```

`models.zip` (v0.2) contains:

| Folder | Use |
|---|---|
| `runs/all_image/` | **Images**: 3 DFF types + OpenAI + StyleGAN; web UI default |
| `runs_swap/b4/` | **Video face-swap** detector (EfficientNet-B4, with threshold) |
| `runs_aivid/b4/` | **AI-generated video** detector (EfficientNet-B4 v4, with threshold) |
| `runs/all_openai/`, `runs/all/`, `runs/t2i/` `runs/inpaint/` `runs/insight/`, `runs/all_video/` | Baselines / arms-race experiment / old loose-crop video model |

## Full reproduction

Run in order. Times measured on an M2 Max (64 GB); needs about 20 GB of disk.

```bash
# 0. Environment
uv sync

# 1. DFF: download 4 zips (5 GB) → resize → split (~10 min + download)
uv run prepare.py

# 2. The 4 DFF models (~3 h)
./run_all.sh
#    results: runs/<name>/results.json, logs: logs/

# 3. OpenAI images
#    Option a: use the released images (recommended, identical results)
curl -LO https://github.com/coobabm/dff-detector/releases/download/v0.1/openai_faces_256.zip
mkdir -p data/img256 data/openai
unzip openai_faces_256.zip -d data/img256 && mv data/img256/meta.json data/openai/
#    Option b: generate your own (~2 h, needs an API key; OpenAI output is random, so images will differ)
export OPENAI_API_KEY=sk-...
#    export OPENAI_BASE_URL=...   # set this if using an OpenAI-compatible proxy
uv run gen_openai.py --n 100 --models gpt-image-2            # images 0–99
uv run gen_openai.py --n 1100 --start 100 \
    --models gpt-image-1.5 gpt-image-2 gpt-image-2.5          # images 100–1099, rotating 3 models

# 4. Modern real photos (~30 min, ~10 GB download; archives are deleted after processing)
uv run fetch_real.py ffhq pexels ppr10k flickr30k easyportrait

# 5. Zero-shot test of DFF models on OpenAI images (a few minutes)
uv run eval_openai.py

# 6. Learning curve (~40 min) → runs_openai/curve.json, runs_openai/n*.pt
uv run openai_curve.py

# 7. Put the final model into the web UI
mkdir -p runs/all_openai && cp runs_openai/n897.pt runs/all_openai/model.pt
uv run app.py

# 8. StyleGAN (~1 h) → runs/all_image
uv run fetch_gan.py
uv run gan_finetune.py

# 9. Video data (~15 GB download; face-swap generation ~5 h on an M2 Max, needs local FaceFusion 3.x)
uv run gen_faceswap.py --clips 120 --targets raw   --faces ffhq --tag hq_raw  --keep
uv run gen_faceswap.py --clips 120 --targets clips --faces ffhq --tag hq_clip --keep
uv run fetch_public_videos.py
uv run fetch_rapidata.py
uv run fetch_aivid_videos.py            # zips thb celebv celebvclips celebv2
uv run recompress_videos.py aivid.csv rapidata.csv hq_clip.csv hq_raw.csv public.csv

# 10. Face-swap detector (~2 h)
uv run extract_tight.py --lists hq_raw.csv hq_clip.csv public.csv --out swap_frames.csv
uv run train_swap.py

# 11. AI-video detector (~2.5 h)
uv run extract_tight.py --lists aivid.csv rapidata.csv hq_clip.csv hq_raw.csv public.csv recomp.csv --out aivid_frames.csv
uv run train_swap.py --frames aivid_frames.csv --task aivid --out runs_aivid/b4

# 12. Scan a video
uv run scan_swap.py your_video.mp4                       # face swap
uv run scan_swap.py --model runs_aivid/b4 your_video.mp4 # AI-generated
```

Notes:

- All random seeds are fixed at 0, but GPU training is not fully deterministic, so reproduced numbers will vary slightly (usually ±1%).
- Pexels images come from the Pexels CDN; a few may have been removed by their authors and are skipped.
- `gen_openai.py` skips images that already exist, so you can rerun it after an interruption to continue.

## Limitations

- OpenAI test and training images come from the same prompt template. Selfies, group photos, and images re-compressed by messaging apps will likely score lower.
- Faces only. Images: SD 1.5, InsightFace, gpt-image, StyleGAN2/3; Midjourney, Flux, Gemini etc. are untested.
- Video: frame-by-frame models with no temporal information (flicker, lip-sync vs audio). AI videos that were re-uploaded and re-compressed online are still unreliable; about 6% of real videos are still flagged.
- The FaceFusion videos used to test the face-swap detector come from the same tool as its training data (with different people, scenes and swapped-in faces). Other tools such as DeepFaceLab were only tested via FF++ / DF40.
- When a new generator appears, the detector needs new samples and fine-tuning again. That is the arms race.
